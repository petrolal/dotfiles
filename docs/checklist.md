## Integration (in progress)

- [x] Wire `DesktopEntryScanner` output into the render layer's node layout — originally `NodeLayout.java` (centered grid), since replaced by `OrbitLayout.java` (real-time category-ring orbits, see below) + `OverlayCamera.worldToScreen` (projects each node's live world position to screen pixels so its label tracks it, instead of a separate decorative label row). Along the way, fixed a real bug in `DesktopEntryScanner`: its hardcoded `SEARCH_DIRS` included `/usr/share/applications`, which doesn't exist on NixOS, so it only ever found the 9 entries under `~/.local/share/applications` and missed the 78 under `/run/current-system/sw/share/applications` (Thunar, Chrome, the terminal, ...). Now resolves dirs from `$XDG_DATA_DIRS`/`$XDG_DATA_HOME` per the Base Directory spec, with priority-ordered dedup by desktop-file id. Live-verified under Hyprland via `quick-overlay`: a real grid of installed apps with correct icons/names/labels renders in place of the old demo row
- [x] Wire node selection (mouse/keyboard) to `ProcessLauncher.launch(...)` — mouse click hit-tests via `OverlayCamera.worldToScreen` and launches immediately; arrow keys move a highlighted selection (yellow border quad), Enter launches it (fixed a repeat-launch bug: held Enter fired on `GLFW_REPEAT` too). Keyboard nav was later reworked for rings instead of a grid -- see the orbital-layout item below. Found and fixed a second real bug in `ProcessLauncher`: `Redirect.DISCARD` is a write-only `/dev/null` handle, valid for stdout/stderr but not `redirectInput`, which threw `IllegalArgumentException` on every single launch; because the launch ran inside `ExecutorService.submit()` with the returned `Future` never checked, that exception was silently swallowed — no output, no crash, just a no-op. Fixed by redirecting stdin from a readable `Redirect.from(new File("/dev/null"))` instead. Live-verified under Hyprland: click/Enter both launch real apps
- [x] Rework the static grid layout into a real-time orbital ("solar system") layout — `OrbitLayout.java` replaces `NodeLayout.java` (deleted): apps are assigned to concentric category rings (`Development`/`Network`/`AudioVideo`/catch-all, first-match-wins against each entry's `Categories=`), each getting fixed `(ring, radius, baseAngle, angularVelocity)` orbital parameters once; live `(x, y)` is pure trig from those plus `glfwGetTime()`, recomputed every frame in `OverlayWindow.loop()`. Outer rings orbit slower (loosely Keplerian: velocity falls with `1/sqrt(ring+1)`). A decorative, non-interactive "sun" quad renders at the origin. Keyboard nav reworked to match: left/right move within the current ring (valid at any time since same-ring nodes share one angular velocity, so their order never changes), up/down jump to the nearest-`baseAngle` node in the next non-empty ring. Covered by `OrbitLayoutTest` (ring assignment, relative angular velocity, the position formula, `MAX_NODES` cap) since the layout math has no GL dependency. Live-verified under Hyprland via `quick-overlay`: ran to completion with no exceptions across repeated runs; not independently screenshot-verified (no `grim`/`slurp` available in this environment). See `docs/migration_plan.md` section 7.
- [x] Add a `Cli` subcommand (e.g. `imp overlay`) to launch the overlay — `imp overlay` in `Cli.java`, delegates to `Orchestrator.runOverlay(dryRun)`; `OverlayWindow.run()` renamed to public `start()` (mirrors `Wallpaper.start`/`ScreenLocker.start`) so both `main()` and `Orchestrator` call the same entry point, with `NativeLibraryPaths.install()` moved inside it
- [x] Decide overlay exit behavior (Escape closes without killing launched children) — already true by construction: `ProcessLauncher.launch` starts detached `ProcessBuilder` processes with no handle kept anywhere, so `OverlayWindow.destroy()` (GLFW/GL cleanup only) never touches them. No new code needed, just confirmed and documented.

## Native-image build (in progress)

- [x] Verify `nativeCompile` succeeds with LWJGL on the classpath — it does; `./bin/imp` built, 30.5MiB, `imp overlay`/`imp --help` both run
- [x] Add JNI/resource reachability config if native-image's static analysis misses LWJGL call sites (check against the GraalVM reachability-metadata-repository first — may not be needed) — it *was* needed: the repository has no `org.lwjgl` entry at all, so LWJGL's own `liblwjgl.so`/`libglfw.so`/`liblwjgl_opengl.so`/`liblwjgl_stb.so` JNI bridge libraries were silently dropped from the image, failing with `Failed to locate library: liblwjgl.so`. Fixed with explicit `resources` glob entries in `reachability-metadata.json`. See `docs/migration_plan.md` section 6.
- [ ] Confirm `org.lwjgl.librarypath` resolution works identically from the native binary, not just `./gradlew run` — **it does not.** Confirmed two real gaps: (1) the native binary needs the same `LD_LIBRARY_PATH` the `quick-overlay` Gradle task sets, not wired anywhere yet for a real launch; (2) even with that fixed, the native binary segfaults a few hundred ms into `glfwInit()` on an unattached native thread — a native-image/Wayland-callback-specific bug that does not reproduce on plain JVM (`quick-overlay` works). See `docs/migration_plan.md` section 6 for the full diagnosis. Not fixed: next step is either trying `GLFW_PLATFORM=x11` (XWayland) as a workaround, or accepting `imp overlay` only runs reliably via `quick-overlay` for now.

## Hyprland integration (in progress)

- [x] Add the `windowrulev2` block from `docs/migration_plan.md` to `hyprland.conf` — this repo's Hyprland config is actually `config/hypr/hyprland.lua` (Hyprland's Lua config API, not the classic `.conf` syntax), so added as an `hl.window_rule({ name = "imp-overlay", match = { class = "^(imp-overlay)$" }, ... })` block instead — same effect (float, fullscreen, no border/shadow/rounding, pin, stay_focused) expressed through that API's field names
- [x] Bind a Hyprland keybind to launch `imp overlay` (mirrors the current `Shift+Super+p` → `imp toggle-hud` pattern in `xfce4-keyboard-shortcuts.xml`) — bound to `SUPER + CTRL + O` in `hyprland.lua`, as a new binding alongside (not replacing) the existing `SUPER + CTRL + RETURN` → `xfce4-appfinder`, since the overlay binary doesn't reliably run yet (see below). Includes the `LD_LIBRARY_PATH` the native binary needs (same value `quick-overlay`'s Gradle task sets).
- [ ] Manual test: overlay opens fullscreen, borderless, pinned, doesn't fight workspace switching — **blocked**, not just untested: the native `imp overlay` binary still segfaults a few hundred ms into `glfwInit()` (see the Native-image build section above and `docs/migration_plan.md` section 6), so there's currently no window to apply/verify these rules against via the real keybind. The window-rule block and keybind are wired and ready; what's missing is the native binary actually opening a window. (The plain-JVM `quick-overlay` path was already live-verified working under Hyprland before these rules existed — see migration_plan.md section 5 — but that path doesn't go through the keybind/native binary this item is about.)
- [x] Decide whether true `wlr-layer-shell` binding is ever needed, given the documented limitation — **No.** `imp overlay` is an invoked-on-demand modal launcher, not an always-visible panel/dock; it only needs panel-like behavior (no border/shadow/rounding, pinned, focused) while open, which `stay_focused` plus the other window rule fields already cover. Real `wlr-layer-shell` semantics (screen-anchored, non-stacking, always-on-top of normal windows) matter for things that are supposed to be visible *alongside* other windows at all times, which doesn't describe this overlay. Not planning raw JNI bindings to `wlr-layer-shell-protocol` unless that assessment changes.

## Biopunk Operating Desk (in progress)

See `docs/biopunk_plan.md` for the audit/rationale behind the original
scope. **Superseded mid-build**: the plan originally kept the existing
app-icon orbit grid alongside the new props. A later, explicit instruction
asked for a genuine first-person 3D desk scene (close-up camera, real
meshes, FBO post-processing) and to eliminate the flat icon grid outright.
Done -- `OrbitLayout`/`DesktopEntryScanner`/`IconLoader`/`IconRenderer`/
`QuadRenderer`/`AppEntry` and their tests are deleted, not just unused. This
is a real capability loss (launch any of ~80 installed apps -> 6 fixed
targets: the heart + 5 syringe slots) accepted deliberately, not an
oversight.

- [x] `telemetry/SystemVitals.java` — CPU/RAM `/proc` sampling, shared with `wallpaper.WallpaperEvents` (unchanged from the earlier pass)
- [x] `OverlayCamera` — real first-person framing (eye `(0, 0.75, 1.45)`, target `(0, 0.20, -0.10)`, FOV 55°, near 0.05, far 50), `setLookAt`, and `unproject()` (NDC → world ray via inverse view-projection) for true 3D raycasting. Covered by `OverlayCameraTest`.
- [x] `SphereMesh` / `BoxMesh` — procedural (no assimp) interleaved position+normal(+UV for the sphere) mesh generators. Covered by `SphereMeshTest`/`BoxMeshTest`.
- [x] `HeartRenderer` — real 3D sphere mesh (not a billboard quad anymore), Fresnel rim + CPU-driven bioluminescent pulse/color shift (idle emerald → stressed crimson), vertex-normal displacement for a breathing pulse. Positioned per spec at `(-0.45, 0.22, 0.10)`, radius `0.22`. Click → `xfce4-terminal -e htop` via a true ray-sphere hit test (`Raycaster.intersectSphere`).
- [x] `SyringeRack` — 5 fixed box-mesh slots at the specified local offsets off `(0.48, 0.12, 0.15)`, each ray-box hit-tested (`Raycaster.intersectBox`) and mapped to an app actually installed on this host (confirmed against `nixos/modules/packages.nix`/`config/hypr/hyprland.lua`, not guessed): Terminal → `xfce4-terminal`, Browser → `google-chrome-stable`, Editor → `emacs`, Chat → `telegram-desktop`, Files → `thunar`. Click triggers a decaying plunge/emissive-flash animation, then launches via `ProcessLauncher`.
- [x] `Raycaster` — pure ray-sphere and ray-box (AABB slab test) intersection, no GL/JOML-matrix dependency of its own. Covered by `RaycasterTest`.
- [x] `PostProcessPipeline` — offscreen FBO (color `GL_RGBA8` + `GL_DEPTH24_STENCIL8` renderbuffer, resized on window resize) with a composite pass (radial chromatic aberration, breathing vignette, CRT scanlines, CPU-load color bias). The whole 3D scene renders into it; text labels are drawn afterward, directly to the default framebuffer, so they stay legible and don't fight the FBO's own depth buffer.
- [x] Real depth/cull state: `GL_DEPTH_TEST` (`GL_LEQUAL`), `GL_CULL_FACE` (`GL_BACK`), `GL_BLEND` all enabled in `OverlayWindow.init()`.
- [ ] `ScryingMirror` — deferred, not stubbed: needs real-time rendered content (ECG waveform + live Hyprland workspace state as a texture), a materially bigger unit of work than geometry alone.
- [ ] `ValveControl` — deferred: scroll-driven `wpctl set-volume @DEFAULT_AUDIO_SINK@ 5%+/-` plus a rotating dial mesh: no scroll-wheel GLFW callback wired yet.
- [ ] `PetriDish` — deferred (true Wayland drag-and-drop has no GLFW support; see plan doc for the hotkey-staged-tray alternative)
- [ ] Overlay shader hot-reload (`Shader.java` is still inline GLSL text blocks, not file-backed + `WatchService`)
- [ ] Precondition carried over from the overlay checklist above: the native-image `imp overlay` segfault on `glfwInit()` — every biopunk feature is only live-verifiable via `quick-overlay` until that's fixed. **None of the rendering in this section has been visually verified under Hyprland** (no GPU/display in the environment this was built in) — `./gradlew compileJava test` passes (38 tests), but run `quick-overlay` before trusting any of it on screen.
