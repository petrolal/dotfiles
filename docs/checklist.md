- [x] GLFW window creation + OpenGL context (core profile, version pinned) — `OverlayWindow.java`
- [x] Set `GLFW_X11_CLASS_NAME` / Wayland app-id to `imp-overlay` so Hyprland rules match
- [x] Render loop (clear, swap buffers, poll events) on its own thread, never blocking on `ProcessLauncher`
- [x] JOML-based perspective camera + view/projection matrices — `OverlayCamera.java`, wired to `OverlayWindow`'s framebuffer-resize callback
- [x] Basic mesh/quad renderer for app nodes — `Shader.java` + `QuadRenderer.java`, draws a demo row of placeholder quads in `OverlayWindow`'s loop. Live-verified under real Hyprland/Wayland on this NVIDIA PRIME host via `./gradlew quick-overlay`: window opens, 5 blue quads render, clean exit on Escape
- [x] Font rendering via `lwjgl-stb` (stb_truetype) for app labels — `FontAtlas.java` (bakes a TTF resolved via `fc-match`, not a hardcoded Nix store path) + `TextRenderer.java` (screen-space orthographic text quads). Live-verified under Hyprland via `quick-overlay`: labels render correctly under the demo quads
- [x] Icon texture loading (theme lookup + fallback for missing icons) — `IconLoader.java` (bounded-depth search across Chicago95/hicolor, since their on-disk layouts differ -- see its javadoc; `stb_image` PNG decode; magenta/gray checkerboard fallback texture) + `IconRenderer.java` (textured quad, separate shader from `QuadRenderer`'s flat color). Live-verified under Hyprland via `quick-overlay`: 3 real icon hits (terminal, file manager, app finder) and 2 deliberate misses (Chrome, a fake name) both render correctly

## Integration (in progress)

- [x] Wire `DesktopEntryScanner` output into the render layer's node layout — `NodeLayout.java` (centered grid, sorted by name, capped at `MAX_NODES = 24` since scrolling/pagination isn't built yet) + `OverlayCamera.worldToScreen` (projects each node's world position to screen pixels so its label tracks it, instead of a separate decorative label row). Along the way, fixed a real bug in `DesktopEntryScanner`: its hardcoded `SEARCH_DIRS` included `/usr/share/applications`, which doesn't exist on NixOS, so it only ever found the 9 entries under `~/.local/share/applications` and missed the 78 under `/run/current-system/sw/share/applications` (Thunar, Chrome, the terminal, ...). Now resolves dirs from `$XDG_DATA_DIRS`/`$XDG_DATA_HOME` per the Base Directory spec, with priority-ordered dedup by desktop-file id. Live-verified under Hyprland via `quick-overlay`: a real grid of installed apps with correct icons/names/labels renders in place of the old demo row
- [x] Wire node selection (mouse/keyboard) to `ProcessLauncher.launch(...)` — mouse click hit-tests via `OverlayCamera.worldToScreen` and launches immediately; arrow keys move a highlighted selection (yellow border quad), Enter launches it (fixed a repeat-launch bug: held Enter fired on `GLFW_REPEAT` too). `NodeLayout.Grid` now exposes `columns` so up/down can move by a full row. Found and fixed a second real bug in `ProcessLauncher`: `Redirect.DISCARD` is a write-only `/dev/null` handle, valid for stdout/stderr but not `redirectInput`, which threw `IllegalArgumentException` on every single launch; because the launch ran inside `ExecutorService.submit()` with the returned `Future` never checked, that exception was silently swallowed — no output, no crash, just a no-op. Fixed by redirecting stdin from a readable `Redirect.from(new File("/dev/null"))` instead. Live-verified under Hyprland: click/Enter both launch real apps
